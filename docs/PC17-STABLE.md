# PC17 稳定版实现与验收约定

日期：2026-11-15（Asia/Singapore）  
状态：实现中；本文说明 PC17 对原稳定版设计的具体收敛，不构成已发布或验收通过声明。

## 目的与兼容边界

PC17 在 PC16 的统一 ProfilePlan/RoutePlan 基础上增加启动去营销、首页主题入口、供应商默认凭据与参数、协议能力说明和 Profile 桌面快捷方式。保持 ShardBrowser 既有组件、间距、表格与菜单设计，不引入新的视觉体系。

外层 `docs/STABLE_VERSION_DESIGN_2026-11-15.md` 是设计阶段历史稿；存在泛化或与当前核心实现冲突的描述时，以本约定及 `PROXY-CHAIN-POLICY.md` 的已实现路由语义为准。PC17 不重新发明代理链，也不以匹配出口 IP 推断两个代理相同。

## 启动去营销

用户允许“屏蔽或从根本上删除”营销提示。PC17 选择移除全局 `PsTrialModal` 挂载、组件与前端营销 API 封装，不提供重新开启营销弹窗的设置开关。英、中、俄的专用废弃文案一并移除。

这使首次启动、既有资料、登录后和更新后启动共享同一个无营销全局外壳，无需依赖 ProxyShard 的 `show` 返回值、是否绑定 API Key、关闭记录或网络是否在线。主动打开的供应商管理、订单和购买页面不属于本次启动营销弹窗删除范围。

后端 `ps_trial_offer` 命令保留用于上游接口兼容；前端无自动调用入口。不能将本次移除解释为已经删除所有供应商业务功能。

定向 E2E 使用“无 API Key + 服务端返回 100 MB 优惠 + 重载启动”反例；真实 Portable 启动验收需要在最终 PC17 EXE 上独立记录。Mock 通过不替代原生 EXE 验收。

## HK_NAT_VPS 测试策略

用户确认 HK_NAT_VPS 的 NAT/IPv4 线路有问题。PC17 不把它作为单层、第一层或产品稳定性的验收基准，不修改 VPS、端口、系统代理或 Sparkle 策略。

允许在已验证稳定的第一层之后，将 HK_NAT_VPS 作为第二层进行特定链路观察。这个决定是本项目的测试策略，不应写成针对该节点名称、ID、地址或端口的产品硬编码，也不应禁止用户手动选择自己的节点。

第一层到 HK_NAT_VPS 的 TCP 可达性、代理握手、网页内容和出口信息分别记录。第二层失败保持失败，不自动直连网站。第二层通过的结果也不能转记为该节点从本机单层直连通过。

## 供应商模板、凭据和代理实例

三个对象的职责分别为：

- 供应商模板：非敏感默认值、字段结构、地区代码和生成规则。
- 本机供应商偏好：用户选择的默认主机、提取服务器、套餐、协议和加密凭据引用。
- 代理实例：生成或手动保存的具体主机、端口、协议、用户名、认证引用和 Profile 绑定。

1024Proxy 的账密生成与 TNBProxy 的白名单提取必须区分。账密保存不证明提取 API 接受 HTTP Basic；TNB 的提取地址也不是最终浏览器代理入口。默认主机或 API 地址可由用户覆盖，模板更新不能覆盖其保存值。

凭据写入沿用当前本机系统加密和设置权限边界。JSON 导出、复制、日志和错误提示不能通过新增供应商字段泄漏默认凭据；普通代理已有的显式导出行为需保持兼容并明确其范围。PC17 不声称账户和团队端具有尚未实现的系统凭据库能力。

地区选择沿用已有可搜索的国家、州/省、城市数据接口；上一级改变时清理不再有效的下级选择。供应商未提供数据应显示其状态，不能伪造可选地区。

## 协议能力模型

当前运行协议为 HTTP、HTTPS、SOCKS5。HTTPS 表示“连接代理服务器本身使用并验证 TLS”，不等同于 HTTP 代理访问 HTTPS 网站。普通 SOCKS5 不自带 TLS。

能力声明、已验证观察和运行协议三个层次独立：

| 层次 | 职责 |
|---|---|
| 运行协议 | 决定握手、认证及 TLS 行为，必须有对应实现 |
| 能力声明 | 供应商声明支持 CONNECT、UDP、IPv4、IPv6 等，不能作为成功结果 |
| 检测事实 | 当前路线、时间、协议阶段、正文及出口观察，不改写运行协议 |

SOCKS5 over TLS、HY2、VLESS 等没有运行实现的协议不能出现在可保存/可启动的协议选项中。可以在说明中指出“不支持”，不能仅通过能力复选框让它看似可用。未验证 UDP/IPv6 标记为未验证；受保护的链路 TCP-only 不应被节点能力声明解除。

能力字段可用作兼容的声明元数据，但不是执行开关，不能绕过 RoutePlan、TLS 校验、凭据权限或 Fail Closed。网页出口成功也不能推断节点支持 UDP 或双栈。

## 主题与桌面快捷方式

首页顶部主题控件复用现有 theme 状态与浅色、深色、跟随系统设置，不创建第二份主题存储。切换立即生效；设置页旧草稿不能覆盖首页新提交。图标、菜单、字号和触区沿用当前 UI kit。

Profile 桌面快捷方式绑定 Profile ID；命令行不含代理密码、API Key 或订阅 URL。启动读取当前保存配置，经过现有授权与 ProfilePlan，再调用正常启动流程。已有 Launcher 使用现有单实例转发，不能为了快捷方式开第二套可写 store。

已运行 Profile 应激活现有窗口，不能重复创建 Session。Profile 更名仍能启动；Profile 不存在或回收站状态需给出可操作反馈。默认启动 URL 去重沿用已实现的 tabs-only helper，不能为快捷方式开放调试端口或削弱代理保护。

## 验收与发布记录

PC17 最终验收应按当前候选源码、EXE 哈希及实际引擎身份留证，至少包含：

1. 有营销响应、无供应商 Key 的启动不出现营销 UI，重新启动仍无弹窗。
2. 首页主题切换与设置页、重载持久化共享状态，最小窗口无工具栏溢出。
3. 供应商默认参数和凭据可保存、重载、覆盖；取消不误写，非敏感默认值与秘密分开导出。
4. 未实现协议无法被选择并保存；声明能力不伪装成实测成功。
5. 快捷方式创建并实际启动指定 Profile，重命名、重复运行、缺失 Profile 和受保护 Profile 路径符合已有权限。
6. 统一路由与 Fail Closed 的相关回归通过；不使用 HK_NAT_VPS 单层失败来修改产品策略。
7. 当前 Portable 真实启动、旧资料保留、正常退出和交付 SHA256 对应同一候选。
8. 新增 E2E 纳入 `scripts/verify-patch.ps1` 的唯一 `uiTests` 清单，离线脚本检查对应必需项，不能只依赖本机手动调用。

当前状态：实现和定向检查进行中。未完成最终候选绑定、全量门禁、原生快捷方式及 PC17 Portable 验收前，不标记稳定版已发布。

## PC17 凭据保存与导出边界

本轮仅对供应商默认配置中的秘密使用 Windows DPAPI：1024Proxy、TNBProxy 和自定义供应商的默认凭据分别保存，普通参数与秘密分离，公开设置响应不返回密码。保护绑定当前 Windows 账户；跨账户恢复需要重新输入供应商凭据。

已有代理节点继续使用原 ProxyStore 的读取和保存格式，不执行整库账密加密迁移，不宣称现有节点或新生成节点的所有账密均已加密。节点 ID 与环境 proxy_id 绑定保持；本轮不引入密文存储格式导致的 PC16 回滚不兼容。供应商默认凭据的保护与已保存代理节点的存储是两个边界。

代理文本导出默认提供不含账密的地址；包含账密必须由用户显式选择，沿用现有一分钟后清理剪贴板的机制。定向 Mock E2E 已验证地址导出不含登录信息，以及显式凭据导出一分钟后清空；这不代表操作系统剪贴板历史或其他剪贴板管理软件中的副本也会删除。
